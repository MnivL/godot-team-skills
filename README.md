# Godot 团队开发 Skills

面向 Godot 新手团队的六个可独立使用的开发技能。版本：0.5。

每个技能自带必要约定、参考和模板，不依赖作者的其他指南或旧聊天。游戏工程与美术素材不包含在本仓库中。

| 技能 | 使用场景 |
|---|---|
| `godot-project-setup` | 从零建工程、新需求落位、骨架演进、资源迁移 |
| `godot-architecture-design` | 玩法与表现分层、模块职责、接口和状态归属 |
| `game-task-design` | 需求拆分、文件边界、任务与验收 |
| `godot-module-dev` | 实现功能、修复问题、替换表现 |
| `godot-code-review` | 指定提交/差异/PR 的只读审核 |
| `github-pr-handoff` | 内容检查、同步 main、rebase、验证后快进交付 |

## 获取与使用

```powershell
git clone https://github.com/MnivL/godot-team-skills.git
```

也可使用 GitHub 的 Code → Download ZIP。把需要的完整技能文件夹复制到工具支持的技能位置；Codex 项目内可使用 `.agents/skills/`。不要只复制 SKILL.md，参考、模板、脚本和 agents 元数据也要保留。已有同名技能时先比较版本和个人改动，不直接覆盖。

启用并被工具发现后，可以直接描述需求让 AI 匹配技能，也可显式点名，例如 `$godot-module-dev`。自动匹配不是每次保证；其他 AI 工具按各自技能机制导入。

详细步骤见 [技能包使用说明](技能包使用说明.md)。`版本清单.json` 提供文件 SHA-256，便于团队核对版本。

## 团队默认规则

- 游戏工程和运行目录统一英文小写 snake_case，新正式工程默认 `game/project.godot`；中文说明仍可使用中文文件名。
- 按功能组织，规则/表现、机制/编排、配置/运行态分离；联机共享结果由权威端确认。
- 并行开发使用独立工作目录与任务分支，公共配置和主地图按当次编辑者协调。
- 所有有写权限的成员可按任务分支、fetch、rebase、验证、普通快进推送 main 的流程交付，不强制 PR 审批；不强推 main。
- 素材、大文件、缓存和个人工具配置不上传游戏 GitHub 仓库；本仓库附忽略模板和只读提交检查脚本。
- 缺环境时标明未执行，静态检查、引擎启动、画面/输入与双机/异地验证分别记录。

公开仓库允许任何人查看、下载和克隆，无需加入团队。公开不等于任何账号都能直接推送；没有写权限的成员可以 fork 后提 PR。
